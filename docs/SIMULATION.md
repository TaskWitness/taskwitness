# 仿真研究

本页所有内容都是**合成数据**。它展示的是在仿真器的假设下、已知真值的情况下，TaskWitness 随着设备变差会有怎样的表现，并不是对任何真实设备的测量。重新生成：`python examples/simulation/study.py`（默认规模约 15 分钟）。

## 原理，以及如何避免“自己给自己打分”

- 每个回合都由一个**潜在的物理经过**生成：物体被松开并静置在称重板上、弹出去了、被夹爪一直握着、是错误的物体、是遗留在板上的东西，等等。称重、夹爪、开关和视频数据流由这一经过加上真实的不完美因素生成：噪声、漂移、尖峰、落地后的振荡、丢样本、零点偏移、接触抖动、冻结在最后位置的视频跟踪器、遮挡，以及视频与传感器之间的时钟偏差。
- **标签来自这一经过，从不来自任何 Oracle**，并且和真实的人工标签一样是二元的（PASS 或 FAIL）。UNKNOWN 只可能是验证器的回答。
- 混合中故意包含 Oracle **并非为之设计**的失败：试验中途另一个重量相当的物体落到称重板上，同时跟踪器卡住，于是两个通道都被骗过。因此报告的误判通过率不会平凡地为零。
- **纯视觉基线是位置检查**（回合结束时被跟踪的物体是否在目标区内），不是学习得到的判定器。FailBench 报告最好的真实 VLM 判定器平均平衡准确率约为 0.77，所以真实的基线表现会与这里不同。请把纯视觉各列理解为“仅凭视频证据能支持什么”，而不是对某个具体系统的模型。
- **如何阅读 UNKNOWN 各列。** “全部”包含故意设置的模糊情形（掉线、物体搭在边缘、夹爪压在板上、错误的物体），所以数值较大。“普通成功”只是正常的成功放置，反映的是设备给正常试验带来的代价。
- 每个单元格 1,500 个回合，种子为 1；区间为 95% Wilson 区间。误判通过是在真实失败中计算的，误判失败是在真实成功中计算的。

|---|---|---|---|
| 100 | 100/100 | 31.0 | 48 |

一个规划数字：在 lab 设备上，任意时刻有效的序贯检验需要多少次试验，才能说 TaskWitness 的误判通过少于纯视觉检查。中位数 31，第 90 百分位 48，100 次运行全部在 600 次以内得出结论。这是个乐观的数字，因为这里的基线很弱；面对更强的判定器，差异更少，需要的试验也更多。


## 这没有说明什么

- **失败类型和噪声水平都是假设。** 混合比例（例如 8% 的试验以物体仍被握着结束）和每一个噪声数值都是作者的选择，只有腕部传感器的数值来自真实数据（[REAL_DATA.md](REAL_DATA.md)）。不同的混合会得到不同的比率；本研究关注的是方法如何*变化*以及它无法判断什么，而不是绝对比率。
- **Oracle 和仿真器出自同一作者**，所以有共同的盲区。本研究确实发现了真实的缺陷（遗留物体被算作成功、慢速开关采样把轻擦算作按压、按压次数上限忽略了未能判断的接触），这正是它的用途，但仿真器无法发现作者没想到的失败。
- **这里从未有过真实的传感器。** 本文件没有任何内容说明称重传感器或按钮开关的行为与仿真相同。真正的验证需要 [EXPERIMENT_GUIDE.md](EXPERIMENT_GUIDE.md) 中的实验。
- **纯视觉基线按构造就很弱**（见上文）。

## 复现

```bash
python examples/simulation/study.py                     # 全部表格
python examples/simulation/study.py --n 400             # 更快
taskwitness simulate place --n 1000 --preset lab --set load_noise_g=1.0 --out sim
taskwitness evaluate sim --by failure_mode --order-by trial
```

预设：`clean`、`lab`、`noisy`、`wrist_ft`；任何设置都可以用 `--set 名称=数值` 覆盖。
