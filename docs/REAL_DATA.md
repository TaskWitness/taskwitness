# 用真实数据测试：REASSEMBLE

快照时间 2026-10-21。以下内容都可以用 `examples/real_data/reassemble_grasp.py` 复现。本仓库**不**分发该数据。

## 为什么选这个数据集，它不能说明什么

TaskWitness 的主要 Oracle 读取目标下方的称重传感器，或按钮自身的触点开关。**据我检索，没有任何公开机器人数据集记录这两种信号**，所以放置和按钮 Oracle 目前无法用公开数据测试。我查看过的数据：

- **FailBench 的数据来源**（arXiv 2609.03611：14 个公开来源、2,197 次尝试）、RoboFail、UR5-Fail：只有视频和标签，没有外部物理传感器。
- **ArmnetBench**（SO-101，每回合一个成功标签）、LeRobot 上的按按钮数据集、RoboMIND：要么是成功演示，要么是策略回放，没有力或接触传感；RoboMIND 还剔除了失败回合。
- **RH20T**：有力/力矩数据，本次未检查。
- **REASSEMBLE**（Sliwowski 等，TU Wien 2025，CC-BY-4.0，[arXiv 2502.05086](https://arxiv.org/abs/2502.05086)，[数据记录](https://researchdata.tuwien.ac.at/records/0ewrv-8cb44)，使用其 LeRobot v3 移植版 [`robot-lev/reassemble`](https://huggingface.co/datasets/robot-lev/reassemble)）：Franka 机械臂在 NIST 任务板上的装配与拆卸，共 149 段录制、4,845 个动作片段，每个片段都有**人工标注的成功标签**，并有 30 fps 的夹爪指位和腕部力/力矩。这是最接近的数据，所以我用了它。

它支持的是一个与放置、按钮 Oracle **不同且更窄**的测试：新增的 `GraspOracle`，根据夹爪手指最终停在哪里来判断抓取。夹爪宽度是机器人自身的本体感知，因此它独立于策略自报的成功结果和视觉，但**不是外部传感器**。这检验的是原则（物理证据优于信任“已完成”，并带有 UNKNOWN 区间），不是对称重 Oracle 的验证。

## 实验方案

在查看测试结果之前确定，使用数据集官方划分（111 个训练 / 37 个测试回合，互不重叠）：

1. 只用“Pick”片段（共 1,192 个；总体失败率 8%）。
2. 对每种物体，用**训练集**中成功抓取的最终手指宽度确定宽度区间 `[min, max]`。训练成功少于 5 次的物体会被跳过（没有任何测试抓取被跳过）。
3. 用 GraspOracle 判定每个**测试集**抓取（248 个：224 次成功、24 次失败），UNKNOWN 边界为 1 mm，默认的“手指已停止”阈值为 0.5 mm。
4. 与两个基线比较：*信任片段已结束*（总是 PASS，即不做检查的系统会给出的答案），以及*不带区间*的检查“夹爪没有完全张开”。

**披露。** 第一次运行发现 63 个 UNKNOWN 中有 56 个是“片段结束时手指仍在移动”。随后我对这个阈值使用了本仓库自己的保形校准（只用**训练集**成功样本拟合）。α = 0.1 是运行前确定的；α = 0.05 是敏感性运行。由于我已经看过测试集的分解结果，校准后的几行应当视为受其启发。

## 结果（测试集，24 次真实失败）

| 判定者 | 误判通过（24 次失败中） | 误判失败（224 次成功中） | UNKNOWN | 做出判定时的准确率 |
| --- | --- | --- | --- | --- |
| 信任片段已结束 | 24/24 = 100% [86%, 100%] | 0% | 0% | 90.3% |
| 不带区间：夹爪没有完全张开 | 21/24 = 87.5% [69%, 96%] | 0% | 0% | 91.5% |
| **GraspOracle**，固定 0.5 mm 稳定性阈值 | **2/24 = 8.3% [2.3%, 25.8%]** | 2/224 = 0.9% [0.2%, 3.2%] | 63/248 = 25.4% | 97.8%（181/185） |
| **GraspOracle**，保形稳定性阈值，α = 0.1（1.12 mm） | **2/24 = 8.3% [2.3%, 25.8%]** | 2/224 = 0.9% | 54/248 = 21.8% [17.1%, 27.3%] | 97.9%（190/194） |
| GraspOracle，保形稳定性阈值，α = 0.05（2.51 mm） | 3/24 = 12.5% [4.3%, 31.0%] | 2/224 = 0.9% | 36/248 = 14.5% | 97.6%（207/212） |

区间为 95% Wilson 区间。与“不带区间”检查的成对精确 McNemar 检验：有 19 次失败只被不带区间的检查判为通过，反向为 0，单侧 p = 1.9e-6。准确率一列不能直接比较：GraspOracle 对大约五分之一的抓取弃权，而基线从不弃权。

## 结果说明了什么，没有说明什么

- **这一原则在真实数据上成立。** 在 24 次真实失败中，校准后的 GraspOracle 直接判定失败 10 次，交给人工复核（UNKNOWN）12 次，误判通过 2 次。信任“已完成”会把 24 次全部判为通过；不带区间的检查会通过 21 次。
- **只有 24 次失败。** 误判通过率的区间很宽（2.3% 到 25.8%）。与基线的相对优劣是清楚的，具体比率则不确定。
- **两次漏判是抓错了东西，但宽度恰好在区间内**（最终宽度 4.2 mm 和 7.8 mm，都在各自区间内）。手指位置无法发现这种情况。
- **弃权大多与时机有关。** 在固定阈值的运行中，63 个 UNKNOWN 里有 56 个是“手指仍在移动”，因为标注的片段结束时夹爪还在调整（占成功样本的 20%）。实际部署时应当等手指停下来再判定。
- **保形保证在跨会话时没有成立。** 设定为“已知正常窗口被判为移动的比例不超过 10%”，测试会话中实际为 **16.5%（37/224）**；α = 0.05 时为 **8.9%（20/224）**，而目标是 5%。两者都显著（约 3 个标准误）。训练与测试录像在不同会话之间存在差异，破坏了保证所需的可交换性。请用多个会话的录像来校准，并预期实际比例高于 α。
- **没有说明的：** 称重或按钮 Oracle 的表现，视觉判定器的表现；也没有说明在其他机器人、物体或标注者上是否成立。

## 为什么机器人自带的腕部传感器不能代替称重传感器

同一数据集给出了腕部力/力矩传感器的真实数值（4,845 个片段末尾）：

| | 实测值 | 对比 |
| --- | --- | --- |
| 半秒窗口内的噪声（单轴标准差） | 中位数 **11.6 g** 当量（P10 9.1 g，P90 29.4 g） | 模拟的 `noisy` 设备为 2 g |
| 各片段稳定后的 Fz 读数之间的离散程度 | 四分位宽度 **143 g**，P5 到 P95 约 277 g（与姿态相关的偏置） | 52 g 的方块重 0.51 N |

很轻的物体远低于与姿态相关的偏置。模拟中的 `wrist_ft` 设备使用这些数值：TaskWitness 对每个回合都返回 UNKNOWN（没有误判通过，但也没有判定），这对于不可用的传感器是正确的行为。见 [SIMULATION.md](SIMULATION.md)。

## 复现

```bash
pip install pyarrow numpy
python examples/real_data/reassemble_grasp.py --download data/reassemble     # 约 450 MB，无需视频
python examples/real_data/reassemble_grasp.py --root data/reassemble                       # 固定稳定性阈值
python examples/real_data/reassemble_grasp.py --root data/reassemble --stability-alpha 0.1 # 保形校准，仅用训练集
```

使用该数据请引用原作者：Sliwowski、Jadav、Stanovcic、Orbik、Heidersberger、Lee，*REASSEMBLE: A Multimodal Dataset for Contact-rich Robotic Assembly and Disassembly*，TU Wien，2025，DOI 10.48436/0ewrv-8cb44。LeRobot 移植版由 robot-lev 制作；数据采用 CC-BY-4.0 许可。
